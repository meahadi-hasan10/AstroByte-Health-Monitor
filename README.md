# AstroByte Health Monitor

**An AI-assisted web prototype for astronaut health awareness and decision support**

**NASA Space Apps Challenge 2026**  
**Challenge:** Create Health Monitoring Software for Astronauts on Space Missions  
**Team:** Team AstroByte — Rajshahi, Bangladesh  
**Status:** Interactive prescreening prototype; not a medical device or clinically validated system.

## Project Overview

Long-duration space missions expose astronauts to distinct health and environmental challenges, including radiation, altered gravity, isolation, disrupted sleep, and fatigue. Crew members need accessible ways to review multiple indicators, recognize changing conditions, and communicate concerns.

**AstroByte Health Monitor** explores this problem through a responsive, interactive web dashboard. It brings simulated crew health indicators, transparent rule-based risk explanations, trends, and environmental radiation context into one interface. The prototype demonstrates how an astronaut-facing decision-support experience could help people notice changes and decide what to verify next.

## Implemented Prototype Features

- **Crew health dashboard:** displays synthetic heart rate, blood oxygen saturation (SpO₂), body temperature, sleep duration, fatigue index, and radiation context.
- **Interactive telemetry simulator:** adjust six values and see the dashboard and illustrative risk analysis respond.
- **Mission scenario lab:** switch between Nominal, Fatigue, Low Oxygen, Radiation, and Multi-signal scenarios.
- **Explainable risk analysis:** inspect an illustrative 0–100 heuristic index, status indicators, contributing factors, and suggested verification steps.
- **Health insight panel:** generate a local, deterministic plain-language explanation; optional server-side LLM summaries are supported when configured.
- **Charts and session tools:** view simulated trends, review session history, reset values, copy insights, and export CSV or JSON reports.
- **Accessible interface:** responsive layout, animated space-themed landing page, keyboard-operable controls, high-contrast option, and reduced-motion support.
- **NASA radiation reference:** optionally query and display a separately labeled **historical** radiation sample from NASA OSDR RadLab through the Flask backend, when the external service is available.

## NASA Data Sources and Data Provenance

**Primary NASA source:** NASA Open Science Data Repository (OSDR) — RadLab Space Radiation Telemetry.

- [NASA RadLab Data API documentation](https://visualization.osdr.nasa.gov/radlab/gui/data-api/)
- [NASA OSDR overview](https://science.nasa.gov/biological-physical/data/osdr/)

The optional backend endpoint `GET /api/nasa/radiation` requests a **historical ISS/DosTel example window (April 1–2, 2022)**. If usable records are returned, the website displays a historical data sample and radiation visualization in the NASA Data section.

| Dashboard component | Source and current behavior |
| --- | --- |
| Heart rate, SpO₂, temperature, sleep, and fatigue | **Synthetic demonstration values**; not real astronaut health records |
| Adjustable radiation value | **Synthetic demonstration input** used in the illustrative risk model |
| Trend projection and risk index | Generated by prototype logic; **not** observed clinical measurements or validated predictions |
| NASA RadLab sample | Optional **historical** API query; displayed separately and not treated as current astronaut telemetry |

**Current integration boundary:** NASA RadLab readings are **not automatically fed into the risk-score calculation**. No NASA astronaut personal-health dataset is loaded into the dashboard. Live API availability has not been guaranteed. See `docs/NASA_DATA_SOURCES.md` for further details.

## How It Works

Synthetic inputs / scenario presets → JavaScript analysis engine → Health cards + explanatory risk score → Local health insight + charts + exports.

Optional Flask backend provides server-side LLM summaries (with a configured API key) and on-demand historical queries to NASA OSDR RadLab.

**Technology:** HTML, CSS, JavaScript, Python, Flask, and Requests. The frontend runs without a backend for offline demonstrations.

## Run Locally

### Option 1 — Browser-only demo

Download or clone the repository, then open `index.html` in a modern browser. The simulated dashboard, scenarios, local explanations, animations, and exports work without an API key. NASA and external LLM requests require the optional backend.

### Option 2 — With the Flask backend

Install Python 3 and run from the repository root:

1. Create a virtual environment: `python -m venv .venv`
2. Activate it: Windows `.venv\Scripts\activate` or Linux/macOS `source .venv/bin/activate`
3. Install dependencies: `pip install -r requirements.txt`
4. Start the server: `python app.py`

Then open **http://127.0.0.1:5000**.

To enable optional LLM-generated explanations, configure `OPENAI_API_KEY` **as a server-side environment variable** before starting Flask. `OPENAI_MODEL` can also be set if needed. **Never commit an API key, `.env` file, or other credentials.** If the LLM service is unavailable, the local rule-based explanation remains available.

## Suggested Demonstration

1. Start at the animated homepage and introduce the astronaut-health challenge.
2. Open the dashboard and review six clearly labeled synthetic indicators.
3. Select **Multi-signal** in the Scenario Lab and observe the changing risk assessment.
4. Click **Analyze current health** and **Generate health insight** to review explanations.
5. Show the NASA Data section, distinguishing the historical RadLab query from the simulated dashboard values.
6. Demonstrate session history, an export, or the responsive mobile layout.

## Tests

The repository includes JavaScript analysis-engine tests and Python backend tests:

- `node tests/engine.test.js`
- `python -m unittest discover -s tests -p 'test_*.py' -v`

For Python backend tests, first install `requirements.txt`. Test execution does **not** by itself verify a live NASA API connection or medical validity.

## Responsible Use of AI

- **Local analysis:** rule-based JavaScript logic; **not** a trained clinical AI/ML model.
- **Optional language-model assistance:** the Flask backend can request a natural-language summary through the OpenAI API when a valid server-side key is configured; otherwise it returns a local heuristic explanation.
- **Development assistance:** ChatGPT was used to generate and revise the initial code, interface text, and project documentation. The team is responsible for reviewing, testing, adapting, and explaining submitted work. Additional AI-generated voice, video, or image assets should be credited where used.

The application does **not** diagnose conditions, prescribe treatment, or replace mission medical procedures. Its thresholds, scenario values, and risk scores are illustrative and not validated for real-world astronaut health decisions. More information is available in `docs/AI_USAGE.md`.

## Project Status and Next Steps

This is a **functional demonstration prototype**, not a deployed astronaut monitoring product. Future work includes testing compatible NASA data retrieval end-to-end, connecting appropriately licensed or permissioned physiological datasets, scientifically validating any risk methodology, and evaluating the interface with relevant domain experts.
